Security model

Asks first — enforced, not requested.

Most assistants defend against prompt injection with a polite line in the system prompt. Ithaca enforces it in the runtime. Once a run has read anything from the web or an MCP server, it’s marked tainted — and from then on, writes, code execution and outbound calls need your approval.

  • Seatbelt sandbox

    Every command runs in a macOS sandbox: writes confined to the workspace, your home folder unreadable, no network unless you approve it.

  • Taint tracking

    Web and MCP content is wrapped as untrusted. Memories saved in a tainted run are replayed as data, never as instructions.

  • Local by default

    Bound to 127.0.0.1 with a password, strict cookies, CSRF and DNS-rebinding guards. Fetches to private addresses are blocked at every redirect.

  • Append-only history

    Every step lands in an event log. Runs replay byte-for-byte, so what you saw is what happened.

On-device model

A model of its own.

One command builds ithaca-local: Qwen3-4B fine-tuned on Ithaca’s own agent runs, then quantized to 4 bits with DWQ. It runs — and trains — on a 16 GB Apple Silicon Mac.

Measured, not vibed.

./ithaca eval runs a hundred tasks with real tools in a simulated world — web pages, Gmail and Google Docs in Chrome, Mac apps — including prompt-injection traps and approval checks. Each run is compared with the last, and a regression fails the build.
